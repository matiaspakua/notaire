## Objetivo

V1 axiom 5 requires a Grant to name worktree, write set, required checks, and budget.
Isolator ADR-004 treats grants as data toward a future sole-committer OS runtime, but
adopters cannot yet declare that data in `aisdlc.toml`. Ship a typed optional profile
schema + validate/list/show only — never claim OS isolation or grant enforcement.

## What Changes

- Optional `[[grants]]` tables in the adopter profile (`id`, `worktree`, `write_set`,
  `required_checks`, `budget`; optional `stage`).
- Omit = no-op; unknown `required_checks` refs fail closed against declared gate names.
- CLI `aisdlc grant list|--json` (+ show by id) and `config show` surface grants as data.
- Isolator stub stays `no-evaluable` / `sandbox=false`; no sandbox claim from grants.
- Notaire optional sample Grant for one stage; doctor green; never flip
  `[committer] required=true`.
- FACTORY-FOUNDATION / ROADMAP + store thin plan / remaining-gaps honesty update.
- Amend ADR-004 with a Grant **profile data** note (not Isolator OS shipped).
