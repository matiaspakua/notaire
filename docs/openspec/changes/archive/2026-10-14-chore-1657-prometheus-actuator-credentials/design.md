## Context

The backend requires ACTUATOR_USER/ACTUATOR_PASSWORD (application.properties) and Prometheus scrapes /actuator/prometheus with HTTP Basic. Both must agree, so both read the same root .env.

## Goals / Non-Goals

**Goals:** no committed actuator credential in prometheus.yml; fresh dev stack scrapes without manual steps.
**Non-Goals:** rotating credentials at runtime.

## Decisions

1. **Compose secrets from environment plus username_file/password_file.** Prometheus does not expand env vars in its config, but supports credential files; Compose can mount an env var as /run/secrets/<name>. 2. **Random value generated by a helper, not by Prometheus.** The backend and Prometheus must share one value, so it is written once to the shared env file.

## Riesgos / Trade-offs

- [An existing .env keeps admin/admin] → untouched by the helper unless it is a placeholder; documented.
- [Backend started before the value is generated] → the helper runs before any compose up.

## Testing Strategy
