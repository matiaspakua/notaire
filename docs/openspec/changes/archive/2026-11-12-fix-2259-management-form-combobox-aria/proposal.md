## Objetivo

The rendered pass on the managements create dialog (Chromium, 1280 px and 320 px, axe) found no axe violations and no sideways scroll, but 2 of the 5 required-field errors (Presupuesto, Escribano) were shown in a role=alert that no control referenced: the shared SearchCombobox input had no aria-invalid and no aria-describedby, unlike every other FormField control. Only 3 of 5 invalid fields were exposed to assistive technology.

## What Changes

- `SearchCombobox` merges the FormField aria state (`useFormFieldAria`) onto its input: aria-invalid, aria-describedby (the error) and aria-required.
- New unit tests (red first) for the combobox inside and outside a FormField; new Playwright `TS-0159` for the managements dialog at 1280 px and 320 px (every alert tied to an aria-invalid control, primary >= 40 px, no sideways scroll).
- Evidence: before 3 of 5 errors tied (`aria-invalid` count 3); after 5 of 5 on both viewports; axe 0 violations on list and dialog at both widths.
