## Objetivo

`LoginAttemptService` counts failed logins in one JVM's memory. With more than one replica, or after a restart, an attacker gets N times the allowed attempts (OWASP A07, SR-01).

## What Changes

- Lockout state moves behind a `LoginAttemptStore`; the service keeps its API, threshold and duration.
- `JpaLoginAttemptStore` keeps counters in a `login_attempts` table (username, failed count, locked until, updated at) created by Flyway `V48`; updates take a row lock and run in their own transaction.
- An in-memory store remains for unit tests.
- Idle and expired rows are purged on failure; only the normalised username is stored.
