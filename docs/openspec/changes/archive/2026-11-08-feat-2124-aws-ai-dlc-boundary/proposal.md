# AWS AI-DLC as a method boundary, not a second orchestrator

> Governed by [CONSTITUTION.md](../../../../CONSTITUTION.md). This proposal documents
> **only this change**; permanent documentation remains the single source of truth.

| Field | Value |
|-------|-------|
| GitHub Issue | #2124 |
| Use Case | CU76 — Quality Assurance and Testing Infrastructure |
| Branch | `cursor/feat-2124-aws-ai-dlc-69d3` |
| Gate 1 status | passed |

## Objetivo

AWS AI-DLC is its own phase runner. Loading it beside aisdlc without a boundary would run two lifecycles. Its hooks can execute commands and must never be auto-trusted.

## What Changes

Add plugins/aws-ai-dlc DESIGN.md (phase ownership: owns zero aisdlc stages as orchestrator). Manifest status=boundary, auto_trust_hooks=false. config validate rejects auto_trust_hooks=true. Declare on Notaire as unavailable. Remove planned stub.

## Reglas de negocio

| Rule | Source | New / Changed / Made explicit |
|------|--------|-------------------------------|
| AI-DLC owns no aisdlc stages as orchestrator; hooks are never auto-trusted; plugin stays unavailable until a later non-orchestrating dry plan | CU76 / ADR-003 / #2124 | New |
