## Objetivo

The rendered audit of the MFA screens (#1640 slice 3; Chromium, 1280 px and 320 px, axe) found 0 axe violations and no sideways scroll in any state (security idle, enrolment secret, recovery codes, enrolled, login challenge). Two error-association gaps on the authentication surface: (1) the login challenge reports a wrong code, a malformed code and a lockout through toast.error only: after a wrong code the page has no role=alert and the code input is not aria-invalid; (2) in the enrolment confirm step a role=alert message is shown but the input is not aria-invalid and not described by it.

## What Changes

- `MfaCodeInput` takes an optional `error` passed to its FormField; `MfaChallengeForm` keeps the code error in state (wrong code, malformed code, lockout message), clears it when the user edits the code or switches between code and recovery code; a connection failure stays a toast because it is not about the code.
- `MfaEnrollmentPanel`: the confirm error message gets an id and the input is aria-invalid and described by it.
- Tests updated from toast assertions to inline field assertions (red first) plus a clearing test and a connection-failure guard.
