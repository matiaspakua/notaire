## Objetivo

`test_promtool_accepts_rules` and `test_amtool_accepts_config` only run through `docker run`, so without a Docker daemon (Claude Code cloud sessions, plain runners) they skip and the real validation of the alert catalogue never runs there.

## What Changes

- The two tests fall back to a local `promtool`/`amtool` when Docker is unavailable and skip only when neither exists.
- The cloud toolchain hook installs both binaries at the versions of the compose image tags.
- Negative tests prove a broken rule file and a broken config fail.
