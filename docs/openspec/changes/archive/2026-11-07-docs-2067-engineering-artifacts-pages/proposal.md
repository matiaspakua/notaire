## Objetivo

The Technical docs list pages by folder. A reader sees Business, Architecture and Testing, but not the chain that ties them: requirement, use case, state model, SAD and ADR, OpenSpec change, test plan and cases, threat model, deployment plan and runbooks. A newcomer cannot follow how Notaire was analyzed, defined, built, tested, secured, released and operated, or why each artifact exists. The documentation itself also drifted since the October audit: ADR-030 is missing from the ADR index, CU88 is missing from the traceability matrix, and the SRS still prescribes MySQL without saying it is a historical baseline.

## What Changes

Add an Engineering artifacts page to the Technical docs that tells the artifact chain stage by stage, with counts read from the repository at build time and two isometric explainer figures: an index-card cabinet for the artifacts and a gated line for the AI SDLC on the lifecycle page. Add a guided reading path to the docs overview. Correct the lifecycle steps that still say the pull request waits for product CI. Fix the documentation drift found by a November audit and record the audit.
