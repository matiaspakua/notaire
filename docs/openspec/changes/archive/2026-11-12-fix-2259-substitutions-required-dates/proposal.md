## Objetivo

Found by the rendered forms audit (#2259): the substitutions create dialog sends the form unchecked. The API rejects a substitution without dateStart and dateEnd (400 `dateEnd: must not be null; dateStart: must not be null`, verified on a real stack), but the two date fields are not marked required and an empty submit produces only the server's generic failure, not a field error. The rendered check showed 0 required controls and 0 role=alert after an empty submit.

## What Changes

- `substitutions/page.tsx`: the start and end date FormFields are `required`; saving without them shows `common.fieldRequired` on each missing field (aria-invalid, aria-describedby) and sends nothing; typing a date clears that field's error; opening the dialog clears both.
- New `substitutions-form-validation.test.tsx` (red first).
- The notary pickers stay optional: the API does not require them.
