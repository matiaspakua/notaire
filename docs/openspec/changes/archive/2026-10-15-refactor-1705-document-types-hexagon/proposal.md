## Objetivo

`DocumentTypeController` injects `DocumentTypeRepository`, `ProcedureTemplateRepository` and `SubmittedDocumentRepository`, uses the legacy entity's DTO conversion, carries four `@Transactional`, and holds the same catalog rules as folio types and identification types: search by name, an `in-use` query, locked when in use, delete guard, optimistic locking on the client version.

Differences: "in use" spans **two** tables (procedure templates and submitted documents), and the entity has more fields (`expires`, `dueDays`, `deliveredBy`, `enabled`, `returned`). The legacy entity stays for other consumers listed as debt.

## What Changes

- A pure domain `DocumentType` with creation and change rules and domain exceptions without HTTP status.
- Inbound ports (query, manage), outbound ports (catalog, usage) and use cases holding the rules.
- A persistence adapter mapping the legacy entity, which stays for `SubmittedDocumentController`, the document persistence adapter, case summary, report, reentry and required-documentation services.
- The controller calls the inbound ports only and keeps its DTO and OpenAPI signatures; an advice maps the domain exceptions to the unchanged responses.
- The controller's ArchUnit baseline entries are removed.
- The locked-when-in-use rule stays shaped like folio/identification so it can be extracted after management status (fourth catalog), not copy-diverged.
