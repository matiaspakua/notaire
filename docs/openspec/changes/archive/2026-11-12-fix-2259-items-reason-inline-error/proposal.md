# Forms audit: items dialog shows the required reason as a field error, not only a toast

## Objetivo

Found in the batch rendered pass: the items dialog validates the conditional required reason (discount or surcharge) with toast.error only. No role=alert, aria-invalid or aria-describedby is set on the field, so a screen reader user gets a transient toast and no association, the pattern #2088 moved the administration forms away from.

## What Changes

- `items/page.tsx`: a `reasonError` state set by the failed save, rendered through `FormField error`, cleared when the user types, when the type changes and when the dialog opens.
- The toast is replaced by the inline error (same translated message).
- Tests: the existing required-reason test now asserts aria-invalid and the described error and no toast; two new tests cover clearing on typing and no stale error on reopening.

## Reglas de negocio
