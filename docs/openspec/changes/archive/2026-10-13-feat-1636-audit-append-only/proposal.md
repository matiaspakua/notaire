## Objetivo

`audit_records` can be updated or deleted by the application's database role, so an attacker or a bug with database access can rewrite history (OWASP A08, SR-09). The API deny rule covers the API surface, not the database.

## What Changes

- Flyway `V47`: a trigger function that rejects row UPDATE and DELETE and statement TRUNCATE on `audit_records`, plus `REVOKE UPDATE, DELETE, TRUNCATE` from `PUBLIC` and from the migrating role.
- Database V&V check `60_audit_append_only.sql`: UPDATE, DELETE and TRUNCATE fail; INSERT and SELECT still work.
- Retention/purge path documented: only the table owner, by disabling the trigger inside a reviewed maintenance window.
- Hash chain decided in design.md: deferred.
