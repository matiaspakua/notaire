## Objetivo

The 2026-11-23 usage report says adoption 25% and hit rate 0% of 49 reads. The log shows why: agents call RepoLens and `rg` through Bash, which the hook never sees (76 CLI calls, none with a session), and 46 of the 63 recorded reads are files outside the repository. A recorded retrieval miss ranks two OpenSpec sections above the component the question asked for. The explorer UI does not explain how an answer was found or what RepoLens saves, although `/api/metrics` already serves the numbers.

## What Changes

- The usage hook records Bash commands: `repolens <tool>` as a RepoLens call with the files it printed, `rg`/`grep`/`git grep` as grep, `find`/`fd`/`git ls-files` as glob. `repolens setup` adds `Bash` to the hook matcher. Reads outside the repository are not recorded, and the report ignores those already logged.
- A question that names a code construct (component, function, class, hook, controller, service...) and no documentation word weights documentation nodes by `doc_factor` (default chosen on the tuning tasks, checked on the held-out tasks, overridable in `[ranking.tuning]`).
- The explorer shows, per search, which hits matched the question and which the graph walk reached and through which relation, the stage timings and the answer size in tokens. A new Overview view shows the pipeline with this store's counts and the measured impact: usage report and benchmark arms (recall, tool calls, time, tokens, cost) with caveats.
- `repolens serve --bench <dir>` names the benchmark folder (the environment variable still works). README, CHANGELOG and version 0.7.0.
