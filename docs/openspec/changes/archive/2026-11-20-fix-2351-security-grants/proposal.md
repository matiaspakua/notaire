## Objetivo

Login authority and module grants load the JPA user and role directly. Those reads already exist as domain queries. Security should use them.

## What Changes

- `UserAuthorityResolver` reads `QueryUsersUseCase`.
- `RoleModuleGrantService` reads `QueryUsersUseCase` and `QueryRolesUseCase`.
- An inactive user still gets no authority and no grants. A user with no role still falls back to the type template.
- Audit, reports, and seed code still import `business.*`. The issue stays open.

## Reglas de negocio

| Rule | Source | New / Changed / Made explicit |
|------|--------|-------------------------------|
| Authority comes from the stored user type and is empty when the user is inactive | #559 | Unchanged |
| Module grants come from the assigned role, or the type template when there is no role | #1683 | Unchanged |
