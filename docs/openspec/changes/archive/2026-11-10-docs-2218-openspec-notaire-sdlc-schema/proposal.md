## Objetivo

`openspec new change --schema notaire-sdlc` fails when run from the repository root because the CLI hard-codes the folder name `openspec` and Notaire keeps the tree at `docs/openspec/` (ADR-026). Agents that expect root-cwd discovery stall; the working path (`cd docs` or `seed-openspec-change.sh --create`) is under-documented in skills.

## What Changes

- Document the supported Gate 1 scaffold path: prefer `bash workspace/sdlc/seed-openspec-change.sh <name> … --create`, or run OpenSpec CLI commands from `docs/` so `notaire-sdlc` is discovered.
- Point `.claude/skills/ai-agent-workflow/SKILL.md` and the relevant `openspec-*` skill(s) at that working path.
- Prove discovery with a failing→passing check in `workspace/tests/test_openspec_location.py` (schemas list includes `notaire-sdlc` when cwd is `docs/`; no root `openspec/` folder).

## Reglas de negocio

| Rule | Source | New / Changed / Made explicit |
|------|--------|-------------------------------|
| Agents MUST scaffold notaire-sdlc changes via seed-openspec-change.sh --create or by running openspec from docs/, not by expecting project schema discovery from the repository root | CU76 / #2218 / ADR-026 | New |
