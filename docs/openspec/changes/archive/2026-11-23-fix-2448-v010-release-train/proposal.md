## Objetivo

Release 0.9.0 was cut with no `v0.9 · …` train, so CD aborted at *Release identity coherence* and no Docker image was ever published for it (#2408 repaired the train and the tree-derived assets afterwards). The open release PR #2416 repeats the defect for 0.10.0: `check-product-version-coherence.py --tag v0.10.0` fails with `no milestone titled v0.10 · …`. The release PR still reads `CLEAN` because after #2001 no workflow runs the coherence gate on the bot-generated release branch. The 0.9.0 backfill also published `v0.8.0` after `v0.9.0`, so GitHub shows `v0.8.0` as Latest.

## What Changes

- Add the `v0.10 · Factory production line & delivery gates (2027-03)` train to `RELEASE_TRAINS`, `milestone_policy.py` and `MILESTONE-NOMENCLATURE.md`, and create the GitHub milestone with that exact title.
- The Release Please job runs `check-product-version-coherence.py --tag v<next>` on the release branch after the OpenAPI sync, so a cut with no train fails the job on every push to `main` instead of failing CD after the tag exists.
- Mark `v0.9.0` as the Latest GitHub Release without changing its notes, date, target or assets.
