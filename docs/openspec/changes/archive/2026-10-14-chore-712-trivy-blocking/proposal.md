# Make the Trivy source scan block on CRITICAL and HIGH findings

> Governed by [CONSTITUTION.md](../../../../CONSTITUTION.md). This proposal documents
> **only this change**; permanent documentation remains the single source of truth.

| Field | Value |
|-------|-------|
| GitHub Issue | #712 |
| Use Case | CU78 — Security, Privacy and Compliance |
| Branch | `claude/amazing-curie-n19flr` |
| Gate 1 status | passed |

## Objetivo

The Trivy source scan in `ci.yml` ran with exit-code 0, so a vulnerable dependency never failed a build. #567 (JasperReports) is closed and a local Trivy scan with the CI flags reports zero fixed CRITICAL or HIGH findings, so the gate can be turned on without turning unrelated pull requests red.

## What Changes

- `ci.yml` security job: `severity: CRITICAL,HIGH` and `exit-code: '1'`; the display and upload steps run `if: always()` so the report survives a failure.
- `security/run_gates.py` SEC-SCA-01 and `preflight.sh` use the same severity and exit code.
- Security docs state that the source scan blocks and the image scan stays report-only.
- New `workspace/tests/test_trivy_blocking.py` guards the workflow and the local gate.
