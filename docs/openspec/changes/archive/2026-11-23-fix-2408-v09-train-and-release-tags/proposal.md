# Restore the 0.8.0 and 0.9.0 release cuts

> Governed by [CONSTITUTION.md](../../../../CONSTITUTION.md). This proposal documents
> **only this change**; permanent documentation remains the single source of truth.

| Field | Value |
|-------|-------|
| GitHub Issue | #2408 |
| Use Case | CU76 — Quality Assurance and Testing Infrastructure (release trains) |
| Branch | `fix/2408_v09_train_and_release_tags` |
| Gate 1 status | passed |

## Why

Release 0.8.0 was cut but never published as a tag/Release, and release 0.9.0 was cut with no
`v0.9 · …` train, so version coherence fails on `main` and CD aborts before publishing anything.
This change restores both cuts to a coherent, auditable state.

## What Changes

- Add the `v0.9 · Factory control plane (2027-03)` train to the nomenclature, the milestone policy
  and `RELEASE_TRAINS`, and create the GitHub milestone with that exact title.
- Keep `train_for("0.9.0")` fail-closed for unmapped minors while resolving the mapped one, so
  `check-product-version-coherence.py --tag v0.9.0` passes.
- Publish the missing `v0.8.0` tag at a 0.8.0-versioned commit whose tree passes coherence, and
  create its GitHub Release from the curated 0.8.0 changelog section.
- Attach the documented assets to the `v0.8.0` and `v0.9.0` Releases without changing their
  notes, published dates or target commits. `v0.8.0`'s coherent tag tree lets CD publish images
  and all five assets; `v0.9.0` gets the three tree-derived assets and records the two image-SBOM
  omissions honestly (no image was ever published for that cut).
- Regenerate the Pages release history so it reports product version `0.9.0`.

**BREAKING**: none.
