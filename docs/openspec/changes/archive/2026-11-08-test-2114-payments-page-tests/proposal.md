## Objetivo

The payments page had 80% branch coverage on its busiest page but 28 uncovered branches. Thirty behaviour tests raise it to 92% and fail when the update-versus-create split, the invalid-range rule, the exceeded-balance message or the newest-first order is broken.

## What Changes

`payments-page-actions.test.tsx` (30): list fallbacks, load error retry, the receipt, budget consultation with summary, status labels and ordering, the budget in the address, the date range (client, server, both with a budget, invalid, malformed, address updates), the payment form (required fields, outstanding balance and status, create, edit with PUT, failures) and delete. The budget picker is a small test double.
