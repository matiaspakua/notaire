## Objetivo

Notaire's AI SDLC works, but it is welded to this repository: the Constitution names Maven, JaCoCo and Playwright, three runtimes keep three configurations (`.aisdlc/project.yml`, `fleet-manifest.yaml`, `opencode.json`), and `local-ai/AUDIT.md` §3.5/§4 records that nothing is portable without editing code. Some rules are still prose only: "never add a line to a baseline by hand" has no mechanical check against `main`, and "generic skills must not encode Notaire-only paths" (CONSTITUTION §5) is unchecked. This change extracts the process into a reusable kit, keeps Notaire as its first adopter, mechanizes those two rules, and publishes the case study.

## What Changes

- New module `framework/ai-sdlc/`: a zero-dependency (Python 3.11+ stdlib) CLI `aisdlc` driven by one TOML profile: stage gates with exit codes, `expect = "fail"` red gates, path scoping, evidence ledger, shrink-only baselines and raise-only floors, skills-catalog lint, context budget, commit and TDD checks, built-in change records with live issue verification, report and cost ledger, `init`/`doctor`.
- Templates: generic policy (constitution), agent card, change record, role agents, CI and hook examples.
- Notaire profile `.aisdlc/aisdlc.toml` maps the framework stages to the existing scripts; `preflight.sh` and Process Checks run the baseline ratchet and the skills lint.
- `.claude/skills/ui-design` committed with a unique name and a repository scope note; three skills gain the frontmatter description they lacked.
- Report `docs/300-development/306-ai-sdlc-framework/ai_sdlc_framework.md` with Mermaid and SVG diagrams.
- GitHub Pages AI Factory: `/ai-sdlc/case-study/` and `/ai-sdlc/framework/` pages, history snapshot, animated gate flow.
