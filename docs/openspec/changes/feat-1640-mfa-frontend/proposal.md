## Objetivo

Slice 2 (PR #2245) made `POST /api/v1/users/login` return an MFA challenge and added `/login/mfa` and `/api/v1/mfa/*`, but no screen can complete a challenge, so an enrolled user cannot sign in from the web UI. This slice adds the login challenge step, the enrolment screen and a Playwright test of enrol-then-login with TOTP. Stacked on `claude/amazing-curie-n19flr` (slice 2); retarget to `main` after #2245 merges.

## What Changes

- `core/auth`: `LoginResult` gains `mfaRequired`, `mfaEnrollmentRequired`, `mfaToken`; a pure `resolveLoginOutcome` classifies a login response.
- `core/mfa`: domain helpers (TOTP vs recovery code detection), port `MfaGateway`, use cases `completeLogin`, `beginEnrollment`, `confirmEnrollment`, `disable`.
- `adapters/http/mfa`: gateway over `lib/api-client` for `/users/login/mfa` and `/mfa/*`; `apiPost` accepts an optional Bearer token so the 5-minute enrolment-scoped token can call the enrolment endpoints before any session exists.
- `composition/mfa.ts` wires the gateway.
- Login page: second step asking for a 6-digit TOTP or a recovery code; third step for users who must enrol (policy ENFORCE), reusing the enrolment panel.
- `MfaEnrollmentPanel` and `/dashboard/security`: begin, show secret and `otpauth://` URI, confirm with a code, show recovery codes once, disable with a current code.
- i18n keys `mfa.*` and `login.mfa*` in `messages/es.json` and `messages/en.json`; nav entry for the security page.
- Playwright `TS-0046-mfa-totp-enrol-login.spec.ts`.

## Reglas de negocio

| Rule | Source | New / Changed / Made explicit |
|------|--------|-------------------------------|
| A password login that yields `mfaRequired` never creates a client session; the session is stored only after `/login/mfa` returns `valid=true` | ADR-032 decision 11 | Made explicit |
| Recovery codes are shown once, only in the response of the confirm call, and are not persisted client-side | ADR-032 decision 3 | Made explicit |
| The enrolment-scoped token is held in component memory only and sent as Bearer on `/mfa/enrollment/**` | ADR-032 decision 10 | Made explicit |
