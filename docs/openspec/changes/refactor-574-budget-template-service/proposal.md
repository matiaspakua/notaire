# Budget templates go through a service and repository, not the static JpaControllerProvider

## Objetivo

BudgetTemplateController builds a legacy BudgetTemplateJpaController per call from a static EntityManagerFactory. That bypasses Spring transactions and DI, hides the work behind catch-all handlers and goes stale across test contexts (documented in BudgetTemplateSerializationIntegrationTest). It is the last production user of JpaControllerProvider.

## What Changes

- A BudgetTemplateCatalogService owns list, create, update-notes and delete over BudgetTemplateRepository.
- BudgetTemplateRepository is keyed by the real composite BudgetTemplatePK.
- The controller becomes thin; the global exception handler maps the outcomes.
- JpaControllerProvider is deleted and an architecture test forbids it.
- HTTP statuses and success bodies are unchanged; error bodies become the standard ErrorResponse.
