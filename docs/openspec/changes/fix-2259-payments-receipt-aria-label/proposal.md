## Objetivo

The rendered pass on the payments page and create dialog (Chromium, 1280 px and 320 px, axe) found 0 axe violations, no sideways scroll, all controls labelled, the empty submit showing 3 required errors each tied to an aria-invalid control (after #2281) and a 44 px primary. One rule gap: the row's receipt action is an icon-only button named by title alone, while edit and delete carry an aria-label; ui-ux-design.md requires a translated aria-label on icon-only buttons. It is the only such button in the frontend.

## What Changes

- `payments/page.tsx`: the receipt button gets `aria-label={t("emitirRecibo")}` (title kept as the tooltip).
- One unit test (red first) asserts the aria-label of the receipt action next to edit and delete.
- Evidence recorded in FORMS-AUDIT-PLAN.md.
