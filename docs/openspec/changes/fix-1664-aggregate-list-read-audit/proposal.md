## Objetivo

#1635 audits every `GET /api/v1/people`. The Next.js client calls the people list to fill pickers on many pages, so ordinary navigation writes many identical rows (1,729 audit rows in 18 minutes of the E2E suite). The noise hides real access and moved the audit-log total under `TS-0104`, which failed on CI shard 3 of PR #1658.

## What Changes

- `@AuditPersonalDataRead(aggregated = true)` on the people list handler: the first list read of a user opens a window (default 60 s, `security.audit.list-read-window-seconds`) and later list reads by the same user in that window write no row. The row says it covers the window.
- Single reads by id and searches keep one row each.

## Reglas de negocio

| Rule | Source | New / Changed / Made explicit |
|------|--------|-------------------------------|
| A user's repeated list reads of personal data inside one window are one audit row | #1635 (list reads aggregated), #1664 | New |

## Out of Scope

- Auditing reads of other entities.
- A shared (multi-instance) window store: the window is per instance, which can only add rows, never drop a user's first read.
