# Frontend OpenAPI-generated TypeScript types

Issue [#1260](https://github.com/matiaspakua/notaire/issues/1260) / #1197 Phase 0.5 / CU76.

## Purpose

Keep the Next.js client aligned with the committed OpenAPI contract
(`backend-api/openapi/openapi.yaml`) so field renames fail at `tsc` time, not in Playwright
or production.

## Commands

```bash
cd frontend
npm run openapi:types         # write src/types/api.generated.ts
npm run openapi:types:check   # fail if committed file is stale (also Frontend CI)
```

## Layout

| File | Role |
|------|------|
| `src/types/api.generated.ts` | Generated by `openapi-typescript` — do not edit |
| `src/types/api.ts` | Stable aliases for high-traffic schemas |
| `src/types/index.ts` | Re-exports aliases + remaining hand-written UI types |

## Drift gate

`frontend-ci.yml` runs `npm run openapi:types:check` before `typecheck`. Any PR that changes
`openapi.yaml` without regenerating types fails Frontend CI.

## Migration policy

New hooks and call sites should import from `@/types/api` (or re-exports in `@/types`).
Remaining hand-written shapes in `index.ts` are migrated incrementally; do not reintroduce
parallel DTOs for schemas already aliased.
