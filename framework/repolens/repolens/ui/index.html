What repolens does

repolens reads this repository into a graph of files, symbols, docs, routes and tables, joined by typed relations. An agent asks one question and gets back a few path:line answers, ranked by meaning and by how the code is connected, so it opens the right files instead of searching for them.

Indexing: once, then only what changed

    Answering a question

    1. 1 · anchors

      Match the words

      Keyword search (BM25 over split identifiers), meaning (local embeddings) and exact names, fused by rank. The best code matches and the best doc match become anchors.

    2. 2 · walk

      Follow the relations

      A personalized PageRank walk from the anchors over calls, imports, implementations, tests, routes and tables finds code that never uses your words.

    3. 3 · rank

      Blend and weigh

      20% text, 80% walk. Tests count half unless you ask about tests; docs and styles count less when you ask for code.

    4. 4 · answer

      A few lines, not files

      Four results in detail and four on one line each, with path:line and the relation that put them there.

    Try it in Explore: every result is labelled matched or with the relation that reached it, and the panel shows the time of each stage and the exact text an agent receives.

    How agents use it here

    From this store's usage log: the MCP server, the CLI, and the harness hook that sees reads, greps and shell commands. Observational, not controlled.

    Before repolens 0.7.0 the hook did not see shell commands, so queries an agent ran through Bash (repolens search, rg) counted as calls but not as session adoption, and reads of files outside the repository counted against the hit rate. Older log lines keep that bias.
